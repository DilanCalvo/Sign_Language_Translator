# Web version — ASL letters in the browser

Static web app that recognizes static ASL letters (A–Y, no J/Z) in real time
using the camera. Same model, same math as the desktop app — it runs 100% in
the browser: no backend, no video ever leaves the device.

## Run locally

```bash
cd web
python -m http.server 8000
# open http://localhost:8000            (the app)
# open http://localhost:8000/js/utils.test.html   (the parity test gate)
```

Camera works on `http://localhost` (secure-context exception). On any other
host it requires HTTPS — Netlify provides that automatically.

## Architecture (one screen, vanilla JS, no build step)

```
index.html          UI: camera view, letter + confidence bar, top-3 hints,
                    spelling strip
js/config.js        Tunables COPIED from ../config.py (see rule 3 below)
js/utils.js         Port of normalize_landmarks / PredictionSmoother / LetterBuffer
js/model.js         Loads model/letters/model_weights.json and runs the
                    Dense+BatchNorm forward pass in plain JS (no TF.js — the
                    official converter does not install on Windows)
js/pipeline.js      camera → mirrored canvas → MediaPipe hands → normalize →
                    model → smoother → UI
js/utils.test.html  THE GATE: replays fixtures generated from real capture
                    data; everything must be PASS
model/              model_weights.json + labels + hand_landmarker.task (local copy)
vendor/mediapipe/   Vendored @mediapipe/tasks-vision@0.10.14 (ESM bundle + WASM)
fixtures/           Input→expected-output pairs generated by tools/make_fixtures.py
```

## The four parity rules (breaking any of these = silent wrong predictions)

1. **Mirror before detection.** The desktop app flips the frame BEFORE
   MediaPipe (`src/detector.py`: `cv2.flip(frame, 1)`), so the whole dataset
   was captured on mirrored video. The web app draws the camera onto a
   mirrored canvas and feeds THAT to the landmarker. If predictions are
   garbage while the hand is detected fine, suspect this first.
2. **`js/utils.js` must match `src/utils.py` exactly.** Never edit one without
   the other, and never trust the port by eye — run the test gate.
3. **`js/config.js` values are copied from `config.py`.** If you tune a
   threshold in one place, change the other too (each constant's comment names
   its `config.py` twin).
4. **The MediaPipe runtime and `.task` model are local and version-pinned.**
   Never switch to a CDN copy or bump the version casually: a different
   detector version can produce subtly different landmarks than the ones the
   training data was captured with.

## After retraining the letters model

One command regenerates everything the web app consumes:

```bash
venv/Scripts/python tools/update_web_letters.py
```

Then open the test gate and confirm **ALL TESTS PASS** before deploying.
Skipping this leaves the deployed site silently serving the old model.

## Deploy

`netlify.toml` (repo root) is already configured: connect the repo in the
Netlify UI and every push deploys `web/` with sane cache headers (model/JS
revalidate on every visit; the vendored runtime is cached forever).

## Current scope and roadmap

- **Now:** static letters A–Y. J/Z need motion; `del`/`space` are not captured
  yet — the strip has a Clear button instead.
- **Next (desktop app already does this; web roadmap):** word signs (TCN
  sequence model + body anchor via pose), gloss→sentence translation (LLM),
  voice in/out.
